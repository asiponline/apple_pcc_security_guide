1. Apple Silicon：SEP 管理的每启动数据卷

可变数据放在独立于 Signed System Volume 的数据卷；SEP 管理 storage-key hierarchy，并在每次启动随机化且不保留旧密钥。旧加密卷随后由 mobile_obliterator 丢弃并重建。NVRAM/Preboot 不属于同一密钥随机化覆盖范围，需另行清理。Cryptex 和 PFS 等 Apple 共享资产可作为受限持久缓存，但不得存放用户请求派生数据。

2. Google Cloud：临时可写分区的认证加密

Workload VM 不附带持久设备存储；可写状态位于内存型虚拟盘/文件系统。/var、/home 可写分区使用 dm-crypt 的 AES-256-GCM 叠加 dm-integrity，逐扇区随机 IV，认证标签保存在 VM 内存；密钥每次启动生成且不持久化。host 能读写虚拟盘后端，但 guest 可检测扇区篡改与重放。

3. 推理缓存：静态前缀与用户 KV Cache 分离

Apple 提供的静态 system prompt/prefix cache 不含用户输入，可在受控内存中共享；Apple Silicon 的溢出可写入 per-boot 数据卷，Google Cloud 的静态前缀保存在 CPU DRAM/GPU HBM。用户 KV Cache 则以设备提供的 turn key 加密；密文可跨 turn 暂存，但 PCC 不保留跨 turn 解密密钥。Google Cloud 缓存仅在易失性 CPU/GPU 内存。

4. 密钥保管：SEP 与 KPS 两种架构

Apple Silicon 的请求 REK 私钥由 SEP 保管，并绑定 OS instance 与 SSR/配置封存状态；它不同于数据卷 storage key。Google Cloud 将 KEM 私钥放在独立 Key Protection Service VM，以 TDX 证明和 Workload Services Daemon 的 HPKE binding key 绑定目标工作负载，密钥具有限定寿命并可销毁。
